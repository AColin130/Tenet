# G0 立项关口（Charter / Stage-Gate 0）

G0 回答：**这件事值不值得做、边界在哪、红线是什么、谁对成功负责**。  
在 G0 通过前，AI 与用户 **不得** 把未确认的目标当作既定事实，**不得** 替项目选定最终架构或发布策略。

---

## 关口目的

| 产出 | 说明 |
|------|------|
| **问题与价值** | 解决什么、不解决什么 |
| **边界** | 范围内外、与相邻系统/团队的分界 |
| **合规与许可证红线** | 必须遵守的约束（含第三方、数据、出口） |
| **成功标准** | 可判断「做成了」的表述（非无限 scope） |
| **Tenet 引用方式** | 如何嵌入 `tenet/`、谁维护同步 |

G0 **不是** 详细设计评审；技术选型深度放在 **Discovery**，G0 只定 **谈问题的框**。

---

## 两类 G0（不要混用）

### A. Tenet 产品本身的 G0

描述 **Tenet 这个开源包** 的定位与 v1 范围。维护 Tenet 文档时，以 Tenet 仓库 README + [`../OVERVIEW.md`](../OVERVIEW.md) 及本节后 **「Tenet 产品 G0 检查项」** 为准。

### B. 用户 C++ 项目的 G0

用户使用 Tenet 在自己仓库开工时，必须完成 **项目级 G0**（用下文 **「用户项目 G0 模板」**）。  
AI 应引导用户 **填写并落盘** 到用户自选路径（建议 `docs/charter.md` 或 `docs/gates/G0.md`），**Tenet 不预置该文件**。

---

## Tenet 产品 G0 检查项

维护 Tenet 或评估「Tenet v1 是否闭环」时，逐项满足：

- [ ] Tenet 定义为 **规矩 + AI 引导** 元层，**非** 固定架构脚手架
- [ ] 非目标明确：不提供默认 monorepo/exe/库成品树、不捆绑必选 CI 模板
- [ ] 服务对象：C++ 团队（参照 20+ 人协作习惯）+ 新手在 AI 下可跟随
- [ ] 流程 SSOT 为 `tenet/AGENTS.md` + `tenet/process/*`
- [ ] v1 五件套齐全且互链：AGENTS、OVERVIEW、G0、G1、exit-criteria
- [ ] 双轨 + 轻 Stage-Gate 在 OVERVIEW 中可追踪
- [ ] 语言策略：流程中文；README 顶英下中；无平行英文 process 树
- [ ] 权威链：根 AGENTS 仅路由，`tenet/AGENTS.md` 为唯一流程权威

## 通过标准

**用户项目 G0 通过** 当且仅当：

1. 第 1–7 节 **无空占位**（「待定」须写清何时在 Discovery 关闭）。
2. **非目标** 与 **成功标准** 不互相矛盾。
3. 合规/许可证节已 **显式扫过**（即使结论是「无额外要求」）。
4. 第 8 节记录 **通过** 及签字角色。

**Tenet 产品 G0**：由上节检查项全部勾选，由 Tenet 维护者在合并重大版本文档 PR 时确认。

---

## AI 如何识别「已过 G0」

优先读 **用户项目** 中 G0 文档第 8 节：

- 若 `状态：通过` 且日期、签字存在 → 视为 **G0 已过**，可进入 Discovery（仍 **未过 G1**）。
- 若不存在 G0 文档或状态非通过 → **引导完成 G0**，默认 Discovery 仅做 **与 charter 对齐的调研**，不扩大 scope。

**禁止**：因用户催促而虚构「已通过 G0」；若用户口头说通过，仍须 **补全并落盘** G0 记录后再继续。

---

## 未通过 G0 时

| 角色 | 行为 |
|------|------|
| **用户** | 缩小或澄清问题；或明确搁置 |
| **AI** | 不写正式工程基线；不写长期架构承诺；可协助起草 G0 文档 |
